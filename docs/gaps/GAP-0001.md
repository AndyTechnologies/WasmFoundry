# GAP-0001: `wf build --watch` lands before the cache (plan order 12 → 13)

## What the plan says

The roadmap (`plan.md`, section 149) orders the vertical slices as PHASE 12 = cache,
PHASE 13 = watch. The cache (sections 67–68) fingerprints inputs to avoid re-running
toolchains; watch rebuilds the whole project on every change and therefore hydrates
exactly the problem the cache exists to fix.

## How it was discovered

Watch was implemented while the session that introduced it was interrupted
(power cut) and later salvaged. The behavior itself was already connected to `wf build`
(the whole project), so the salvage chose to finish and validate it rather than drop
working code.

## Impact

`wf build --watch` recompiles every module on every change. It is correct, just slower
than it will be once the cache exists; no behavior is wrong.

## Does it block the current milestone?

No. Watch has correct behavior; cache is a performance layer on top of it.

## Options considered

1. **Drop the watch work and re-land it after PHASE 12.** Safest for plan order, but it
   throws away validated behavior the user already has.
2. **Land watch now, keep the cache in its planned position.** Chosen: watch lands,
   PHASE 12 (cache) stays the next vertical slice, and it can integrate with watch rather
   than arrive after it.

## Decision

Land watch as a documented deviation. Record it here and in the README status table.

## Consequences

- PHASE 12 (cache) remains pending, and when it arrives, watch rebuilds against cached
  artifacts instead of from scratch.
- The watch skips the first-build ordering quirks this implies: none observed. Rebuilds
  on file changes only, debounced, never triggered by `target/` writes.

## Affected tests

- `crates/wf-cli/src/build.rs` unit tests for `should_ignore_event` (output dir, source
  files, editor noise).
- The full workspace gate.

## Affected documentation

- `README.md` status table (PHASE 12–13 row).
- `docs/architecture.md` does not change: watch lives in `wf-cli`'s `build` command and
  never crosses a crate boundary.
